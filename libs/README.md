# Compile-only libraries

Axiom's client API and the ImGui binding its options panels use, which `dev.chromastudio.client.axiom` compiles against. Axiom supplies both at run time, so neither is in the built jars. They are kept here, in Maven's layout, so a build doesn't depend on JitPack, which builds these on request and can be down. Axiom's own jar is never here.

Axiom 6.1.5 for Minecraft 1.21 and 1.21.1 carries its client API as `META-INF/jars/axiomclientapi.jar`, version `1.0.72`, the same file as its build for 1.21.11, built from the API's 1.20.1 sources. Tag `1.0.6.1` has the same classes and signatures; the one difference is that `BallShape.getMaxRadiusForLivePreview` is abstract there and returns 25 in Axiom's copy, which nothing here calls. Main's `v2.0.1` doesn't fit this Axiom: its `IAxiomWorldRenderContext` is missing, and the render methods take a camera, pose stack and projection instead. Axiom's ImGui classes are the same as the pinned binding's.

JitPack's jar at `https://jitpack.io/com/github/Moulberry/AxiomClientAPI/1.0.6.1/AxiomClientAPI-1.0.6.1.jar` has intermediary names. Its SHA-256 is `0fe9aebe000a0a0836b616b29ad4e8335cb43949e94beb57505efbf05f5d25e7`. NeoForge compiles the shared source against Mojang's names, so the jar here is that one remapped with [tiny-remapper](https://github.com/FabricMC/tiny-remapper) 0.14.1 from `intermediary` to `named`. The mappings are the `mappings.tiny` that Loom writes for 1.21.11 with `loom.officialMojangMappings()`, under `~/.gradle/caches/fabric-loom/1.21.11/`. This line pins the same jar as `1.21.11/stable`. Remapped with 1.21.1's `mappings.tiny`, every class and signature comes out the same. Only the bodies of `BallShape$1`, `$2` and `$3` differ, where 1.21.11's mappings left a call to `I18n.get` and a read of `Blocks.STONE` in intermediary names. The jar is only compiled against, so those bodies never run. Its entries were then rewritten in name order with the time 1980-01-01 00:00, so the same steps give the same hash. Its manifest still says `intermediary`, as JitPack wrote it. Fabric compiles against it with plain `compileOnly`, and Loom's remap of the mod jar turns its Minecraft types into the intermediary names Axiom's copy has at run time.

To move to another version, check its classes against the API jar inside the Axiom build it is for, put the jar at the same path here, update this table and the version in `gradle.properties`, and remove the old one.
