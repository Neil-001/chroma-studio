Tests for the Axiom package, run against a stand-in Axiom (`FakeAxiom` and the stand-ins in `com.moulberry`).

- `FakeAxiom` makes `ClientLevel`, `Minecraft` and `Window` without running their constructors, which would need a whole client.
- `FakeAxiom.client` sets a 720-pixel window and a field of view of 70, because `PaletteBlocks` reads a swatch's colour for the viewing scale they give.
- `FakeAxiom.Tools` copies each region pushed into a `LinkedHashMap`, as an immutable copy probes badly on the clustered hashes of a big box's positions.
- Tests without a world have no block tags bound, so grass, dirt and sand don't count as the ground in them. The tests use gravel for the ground, and the tagged blocks show only in the game.
- `ScriptSafetyTest` runs the real Lua as Axiom 6.1.5 runs it: compiled once, then called for each position with `x`, `y` and `z` set and every other global kept. Only Axiom's functions are stood in for, each as its bytecode has it.
- In `ScriptSafetyTest`, `getBlock` gives the block's registry id, and `getBlockState` the state's id negated, less one. `isSolid` asks whether the state an id names has any collision shape: a block id names the block's default state, a negative id the exact state.
- In `ScriptSafetyTest`, `getBlockProperty` gives a property's value by name as a string, or nil when the block hasn't it, and `isBlockTagged` raises an error for a tag the game doesn't know.
- `ScriptSafetyTest` checks that every existing block a script replaces is one its tool would change, that a block with water in it keeps the water, and, separately, that air is filled only with Paint air ticked, and that air, cave air and void air are all filled when it is. That is true of the Lua alone: in Axiom 6.1.5 the Script Brush doesn't call the script for a position that holds void air, so void air stays.
- What the tool would change comes from the tool's own code (`GradientShapes.paintable`, which `GradientTool.paintable` passes on to, Scatter's painter, `RecolourPlan`), which the scripts use too, so those checks can't catch a mistake the script shares with its tool. The test's own `holdsSomething` and `waterlogged` share no code with either.
- `RecolourCasesTest` holds recolours a builder tried in the game and found wrong, read with the game's own textures, and each case in `AxiomCommitTest` is a way changes could get past the check before sending. Keep their cases and their expected answers.
