## Loading and failure

- `AxiomBridge`, `AxiomCommand` and classes reached by script makers must load without Axiom or ImGui. Hide script controls and `/chroma axiom` without Axiom. If an installed Axiom fails, grey them out with `AxiomBridge.whyNot`.
- Register through `AxiomBridge` after Axiom's entrypoint. Construct all tools before adding any to avoid a partial set. `AxiomTools.service` uses the API class's loader because Axiom's jar supplies the service.
- Let failures reach `GuardedTool` unless the tool can recover. `AxiomBridge.fail` disables the integration for the session. In `AxiomInternals`, a failed lookup or call disables the affected feature. Keep resolved handles usable for recovery, such as Undo after a failed hotbar fill.
- `AxiomMask.SCRIPT` and `WINDOW` are optional. Without `SCRIPT`, compile failures are undetectable and hover treats the mask as scripted. Without `WINDOW`, the panel cannot tell whether Tool Masks is open. Destination mask checks still apply.

## Editor and tool lifecycle

- Use `AxiomEditor.enabled` for the player's toggle because `EditorUI.isActive` can lag a frame. Refuse changes if the state cannot be read. Axiom shrinks the game window and routes clicks to its 3D view, so `AxiomEditor.leaveForWindow` uses Axiom's toggle to open Chroma Studio at full size. Axiom preserves the selection, tool and camera through the toggle.
- Read the active block before leaving the editor because Axiom returns stone outside it. Clear the remembered block if the read fails. Check `isImGuiContextActive` before reading the ImGui frame to avoid a native crash.
- Axiom draws only the selected tool and has no editor-close callback. With "Clear tool when swapping" off, `toolDeselected` is the only swap notification. `Drawn` counts missed draws by frame so a stall does not end a stroke. The tool may still draw in the current frame.
- Axiom can reset a tool on a temporary swap, so `SamplerTool.reset` preserves its sample. Clear transient state in `render` because tools render without a panel. Axiom draws Tool Options before `callConfirm`, so a click can change preview options before Apply.
- Axiom's Text tool can retain the sole chunk render override across swaps. `BuildPreview` skips a busy override. Drop the preview before release so a failed release leaves nothing to send, and keep the handle until release succeeds so reset can retry.
- `ToolService.isMouseDown` button 1 follows Axiom's "Use Tool" binding. Axiom fixes the brush ball's radius at stroke start, so refuse a stroke whose radius changed. Axiom's `BooleanRegion` cannot remove a position, so `SamplerTool` rebuilds the outline when removing blocks.

## Sending changes and masks

- Send changes through `AxiomChanges.send` for permissions, server checks and undo. Take `queue` before reading the index, recheck the index immediately before sending, and record the editor visit to prevent plans crossing rebuilds or visits.
- Recompute from the current world, palette and options with the original stroke positions, seed, starting block and radius. Preview caches are display data. Keep all reached positions, including unchanged ones, and invalidate a refused preview before searching again. See [`QueuedChanges`](../../../../../../main/java/dev/chromastudio/core/palette/CLAUDE.md#plans).
- Axiom's API does not apply masks to submitted changes. On the client thread use `MaskManager.getDestMask`, which includes the selection. Tool masks apply while Tool Masks is open, docked or minimised. With it closed, only the selection applies. Fail closed when a mask cannot be read or called.
- Axiom reports Lua runtime errors only through `ToolMaskWindow.luaExecutionError`, which compiling a fresh context can clear. Keep a stroke failed after an error. `AxiomMask.now` compares message identity because each failure creates a new object. Ignore an old error only when Tool Masks is known closed. Compile errors leave no script. `AxiomMask.scriptInvalid` uses `lastLuaCompile` to distinguish an uncompiled tab. Refuse while the mask applies or window state is unknown.
- `AxiomMask.Test` uses a fresh context so edited Lua recompiles. Axiom seeds noise randomly per context unless the script supplies a seed, so retain the first answer per position. `AxiomMask.aloneChanged` uses recorded answers to attribute a refusal without running Lua again. `peek` withholds failed hover answers and skips Lua because hover can leave an error and need not match the stroke.

## Blocks and scripts

- `RecolourPlan.change` changes doors in pairs, even beyond the brush ball. Apply the mask and build boundary to both halves, and read the second before writing the first in case the writer changes the same level. Shade and gradient leave doors alone because the halves could take different steps. Every tool and script preserves water and avoids placing falling blocks. `ScatterBlocks.paintsOver` also protects blocks holding player data, doors and tall plants.
- `RecolourPlan` chooses by block, using the first From palette state or the default. Shading and `SampleKind` count shapes with their full block so sampling and building agree. `FoundBuild` gives the palette brush a local lightness range. Using every block would confine stone to a few middle shades. Keep ground intact without a From palette so brushing a wall leaves the lawn alone.
- `PaletteBrushTool` searches again only when the pointer moves outside its Whole build outline. A search includes the pointed block, so a capped build cannot search every frame. Clear the outline when put away to avoid stale results. `PaletteBrushTool.Bound` binds the palette object because its key can change on rename or be reused after deletion. Keep the binding through rename and refuse a missing From palette so deletion cannot broaden the recolour.
- `GradientShapes.glassPair` pairs glass and panes by id because the index puts them in separate materials. Check that the fallback is glass because iron bars share the pane kind, and mods can name a `StainedGlassPaneBlock` without the `glass_pane` suffix. Avoid unwaxed copper substitutes because weathering changes colour. Cache by state because lit and unlit blocks can differ.
- When reversing the steps, retain `GradientTool`'s endpoints and seed for straightening and "Like the first block". `GradientTool.search` seeds the first material along the gradient line up to the first gap, liquid or excluded ground. Starting only at the first block lets trim cut off the rest. Traversing other materials can spend the search cap on terrain.
- `AxiomScripts` shares eligibility with tools. A gradient script covers the Script Brush's positions, can paint air and leaves shapes alone because Lua cannot resolve counterparts. Require full cubes without block entities for gradient steps. Approximate full-cube eligibility with exclusions and `isSolid(getBlock(...))`, which checks collision on the default state. The recolour script cannot read tool masks and changes both door halves even if the mask admitted one. See the [Script Brush notes](../../../../../../main/java/dev/chromastudio/core/palette/CLAUDE.md#axioms-script-brush).

## Hotbars, icons and panels

- Axiom numbers hotbars from 0 and ignores active-hotbar writes outside creative. Write the active hotbar through inventory and extra hotbars through `AxiomHotbars.set`. Axiom saves extra hotbars per world or server unless global, and only while active, about ten seconds after a change. Keep `AxiomHotbars.INDEX` independent of other handles so Undo can detect a swap after integration failure.
- Axiom gives custom tools a pencil. `AxiomIcons.give` replaces entries with icon proxies and forwards deselection. Axiom 6.1.5 keys bindings by entry identity but omits API tools from that map. Skip keyed entries and roll back incomplete swaps to avoid losing a tool.
- ImGui treats text and tooltip strings as printf formats. Draw through `AxiomPanel` so names containing `%` are safe. Give duplicate labels separate ImGui ids. Defer actions through `AxiomPanel.Layout.later` so later controls do not read cleared state. Apply must run before the tool resets and release focus so Axiom gets the undo key. Read slider values through `held` or `radius` even before the panel draws.
- `AxiomPanel.Layout` packs Apply beside its choices when they fit. Narrow panels can wrap packed rows under the scrollbar, so keep packed and pinned heights separate. Put variable text below controls or after a growing list so the list can absorb the change. ImGui lays out top to bottom, so reserve the previous frame's bottom height and let both parts scroll together when space runs out. Close children in `finally` or Axiom's next draw breaks.
- Give mask and editor failures priority in the status line. Axiom stores no compile error text, so direct the player to Scripting. Use `AxiomNames` with English fallback. Axiom 6.1.5 loads names from `config/axiom/translations.zip` and hardcodes Mask and Scripting in English. Quote names in translations so they need no inflection.
- `EyedropperTool` uses `BlockIndex.material` for one result per material because `materialSet` follows the global technical setting while Match can include technical blocks. Store a position rather than a `TintContext`, which holds the level. Axiom draws outlines without depth, so hover outlines show hidden faces too.

## Shade and sampling

- `ShadeBrushTool` shades shapes by their full block. It skips see-through trapdoors and rotatable blocks whose faces can differ in lightness. Axiom's raycast loses the block over the panel, so retain it there and through a stroke. Show the pointed face in swatches because the matching face averages grass with its dirt sides.
- Take unrestricted shades from the Building Blocks and Colored Blocks tabs, which are empty before joining a world. Skip coal, lapis, raw ore blocks and carved accents so they do not become shades of plain stone. Scatter uses full blocks because random stairs or slabs would face one way and flowers can break in midair. Use persistent leaves to prevent decay.
- `SampleKind` checks plants and ground from the block itself so blocks omitted by the index cannot join separate builds. `SamplerTool` starts over on the first valid sample in a new world or dimension so a missed click loses nothing. Use `PaletteStore.createSaved` so a failed save adds nothing that could be saved twice.
