## State and layout

- Keep `MatchState` and `GradientTab.stepsOnShow` on the client thread. The list outlives the window for Axiom's gradient tool. Read candidate colours and world tints on the client thread before handing a solve to a worker.
- Settings can change without notifying a tab. Run `MatchState.follow` before building controls so they reflect those changes. It also resolves block targets again after index rebuilds, which replace the entries.
- Rebuilding widgets loses typed values and cursor positions. `GradientTab` rebuilds filter controls only for layout or filter changes. `PalettesTab` filters its list without rebuilding the search field.
- `PalettesTab.layoutEntries` guards `setValue` with `loading` because field responders would otherwise mark a palette changed while switching to it. Keep tags and notes unbounded so edits don't truncate imported text. Give presets their full text in a tooltip because disabled fields can't scroll.
- `PalettesTab.layout` replaces `rows` when another palette is selected so its blocks start at the top. `PalettesTab.drawOver` gives `rows` the mouse only inside the entries viewport because rows scrolled out of view would otherwise show tooltips over the toolbar.
- Call `MatchState.remember` after a colour is chosen so a slider drag doesn't fill recent colours.

## Gradient and Match

- `GradientTab.restore` keeps the saved blocks even when current settings would pick others. Resolve pins and steps from the same index build. Retry if a new build lands during restore and solve when a saved block is missing.
- Include exact pinned states in `GradientTab.solve` even if filters omit them. The quality badge measures OKLab ΔE because its thresholds are in OKLab.
- A stop press can survive pinning because pinning skips `Tab.closed`. Clear it on reopening as well as on close. Only a left release ends a stop press.
- `MatchFilters.candidates` excludes invisible models such as barriers because their item texture would pass as a block colour. Block entity models such as chests have their own filter.
- The top of the chroma slider means no limit because some textures exceed its range. `MatchTab` scales viewing distance logarithmically because each doubling halves texture detail.
- `GradientTab.legend` shows step and stop details on a line above the strip instead of tooltips, which covered neighbouring steps and controls. It falls back to a tooltip when the strip is too short for the line.
- `GradientTab.openSwap` keeps the closest block of each material set so shapes of one material don't fill the list. The kind filter chooses the shape.
- `GradientTab.layout` labels the easing and hue cyclers only when the row fits them, and moves the kind and filter buttons to the stops row to make room.
- `MatchTab.build` drops the labels from the face, metric and biome cyclers when their row would otherwise wrap, as it does in longer languages. A wrapped row costs result rows at the minimum window size.
- `MatchTab.buildPanel` sizes a panel to its content and keeps at least two result rows below it, so the list still shows what a filter or biome change does. When that would leave the panel too short, as in longer languages or Grid, the panel covers the results instead. `MatchTab.renderPinned` draws the full list without closing the panel because pinned drawing stops while F1 hides the HUD.
- `MatchTab` samples the biome list swatches on the top face because `Entry.layers` rejects `Face.ANY`. An exception there would empty the panel without a visible error.
- `MatchTab.cameFrom` remembers the selected palette only when a filter arrives through `Handoff`. That is how Analyse opens Match, and the back link returns there.
- `TargetModel` keeps the values of the last picker moved so its handle stays put through gamut clipping and greys. `HUE_MAX` stops below 360 because `Oklch` wraps 360 to 0.

## Dialogs and drawing

- `PaletteDialogs.Export` shows the Axiom hint for `.litematic` because Axiom's Import Schematic doesn't read `.nbt`. It gives the reason "Export and place" is unavailable as a line under the buttons, without a tooltip, because the tooltip would cover that line. `PaletteDialogs.WorldEdit` strips one slash because chat omits the command slash and WorldEdit's commands start with two.
- `SavedGradients` renames the loaded gradient only after the store writes it, so a cancelled replace or a failed write keeps the old name. The replace confirmation builds the gradient when it opens and stores that one, so a change made in another tab can't be saved unseen. A cut-off name shows in the footer because a tooltip there covers the next rows.
- `PaletteDialogs.Axiom` takes its height from the taller of Recolour and Scatter so Copy stays put when the mode changes. An option that changes that height, such as From, reopens the dialog at the new size. Its details scroll in whatever room the window leaves, because a tooltip can't show a long list of left-out blocks.
- `PaletteDialogs.Generate` keeps one random seed until Random replaces it, so Generate saves exactly the blocks the preview shows. Random only fills the fields for the same reason. Like `GradientTab.pool`, it chooses only from `MatchState.filters().candidates`, so every Match filter applies. It ranks every state but keeps only the candidate entries, so a better-matching state outside the pool can't stand in for one in it. Generate saves only once the current preview has been drawn, so a click queued after Random can't save blocks the player hasn't seen.
- `PaletteDialogs.Image` reads and clusters on its own thread because large photos stall the client thread, and drops results from older generations. It matches blocks on the client thread through the same `closest` as Generate and matches again when `poolKey()` changes. It saves only a preview that is drawn and current, never one still reading or waiting on an edit. It draws the thumbnail as fills because `Dialog` has no close hook to release a texture. Its match words share `GradientTab`'s ΔE thresholds.
- Build the `PaletteDialogs.WorldEdit` buttons before setting the From field, whose responder updates them. The dialog draws the unused From field itself because the game's text field looks the same when disabled. It leaves the From field unfocused after //replace is chosen because the game hides a focused field's hint. In `PaletteDialogs.Hotbar`, wait for the rebuilt dialog to draw before accepting Fill, so queued clicks can't confirm it unseen.
- `PaletteDialogs.Confirm` focuses Cancel first so Enter can't delete or overwrite by accident. Its close button, Escape and an outside click go through `Dialog.cancel`, which lets the saved gradient confirmations return to `SavedGradients` and keep the typed name.
- `PanelTab.mouseClicked` gives both widget groups the click when there's no dialog so clicking one group ends typing in the other.
- `MatchTab.panel` and `GradientTab.drawOver` draw a rule under the filter panel title so the first scrolled row reads as part of the body.
- `PaletteDialogs.Import` draws its status under its buttons instead of through `Dialog.status`, which pins text to the bottom edge. It returns focus to the field on the next tick because a click focuses the button after the button's action runs.
- `DioramaPanel` shares arrangement defaults, filtered entries and seed with the exporter so the default export matches the wall shown. Reroll in `PaletteDialogs.Export` replaces that seed only for the export.
- `DioramaPanel.draw` drops widget focus after mouse input so a clicked control doesn't keep a ring that reads as selected. Keyboard focus stays. The 3D scale fits the wall at the default angle so turning doesn't resize it. Legend swatches are cut from the flat wall's texture, so `paint` runs in both views.
- `DioramaPip.renderToTexture` creates a resolver because Fabric's is private. It flips the wall about z because GUI y runs down. `lookThroughALens` swaps near and far for the game's reversed depth. `FIT` leaves room for perspective to enlarge the near end. It lights with `ITEMS_FLAT` because `ITEMS_3D` leaves the wall's front face dark.
- `AnalysePanel` draws its Find blocks buttons itself because they scroll with the findings. Park them off screen each frame so a scrolled-out button can't take a click. Anchor its tooltips below the finding, or above it at the screen edge, so they don't cover its text.
- `ExploreTab` pans hue around the circle through `HueWindow`, which places each hue once within at most 360°. While zoomed, `HueWindow.offset` with a lead keeps a hue a few pixels past the left edge on that side so a point slides off the plot instead of jumping to the right. The lead never exceeds half the hidden arc, so it can't pull a visible hue to the left.
- `ExploreTab.tooltip` places the game's tooltip with its own positioner. The game draws tooltips after the frame, so the block icon can't go inside one and sits in a gap left beside it.
- `Thumbnails.draw` treats pixels at or above the alpha cutoff as opaque so glass on the dark list still matches the colour it was ranked by.
